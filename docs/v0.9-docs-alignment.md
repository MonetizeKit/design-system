# Plan — v0.9 documentation alignment (§13)

## Goal

Brand Direction **v0.9** adds a dedicated **§13 Documentation** section to the board. The goal is the
same single-source-of-truth principle as v0.8: everything the docs board renders should be expressed
by the published design-system packages, so docs (and any future) surfaces consume the brand instead
of re-authoring chrome per app.

This plan also captures the two architectural recommendations from the docs-alignment review and
records which parts are shipped vs. still scoped.

## Why this is not a framework rewrite

The `@monetizekit/design-tokens` architecture already supports cross-framework consumption:

- **Typed source** (`brand.ts` / `palettes.ts` / `types.ts`) → **pure resolver** (`resolve.ts`,
  `theme × palette × mode`) → **multiple emit targets**: JS/TS, `tokens.json`, `tokens.css`,
  `theme.css` (Tailwind v4 `@theme`), `mk-tokens.css` (SDK `--mk-*` contract), and a Tailwind preset.

The friction seen in the docs app was **per-app consumption plumbing**, not a token-framework limit.
The two recommendations below remove that plumbing.

## Recommendation 1 — Centralize the dark-mode contract  ✅ shipped

`tokens.css` now emits the default and per-palette **dark** blocks under **both**
`[data-theme="dark"]` **and** the `.dark` class alias:

- `[data-theme="dark"], .dark { … }`
- `[data-palette="nord"][data-theme="dark"], [data-palette="nord"].dark { … }`

Consumers driving dark via a **class** strategy (Tailwind `dark:`, `next-themes` `class`) now get the
complete brand dark contract straight from the package — inverted neutrals, dimmed `--mk-shade`, the
full shadcn semantic set — and no longer hand-mirror `[data-theme="dark"]` values onto `.dark` per app
for reliable content repaint on a live toggle. The selector policy is a single tested source:
`paletteModeSelector(palette, mode)` (exported from `@monetizekit/design-tokens`).

Result in the docs app: the hand-written `.dark { … }` mirror block in `apps/docs/app/globals.css` was
removed; the contract is now sourced from `@monetizekit/design-tokens` via `@monetizekit/brand/css`.

## Recommendation 2 — Shared documentation primitives (a docs kit)  ◐ started

The §13 primitives live as **brand primitives** (`@monetizekit/brand/primitives.css`, next to
`.mk-verdict`) so brand-only consumers get them without importing the React component stylesheet, with
thin React wrappers in `@monetizekit/ui-react` and contract types for non-React renderers.

Shipped:

- **`Callout`** (`.mk-callout*`) — status-color panel: `note`→yellow, `tip`→mint, `info`→cyan,
  `warn`→pink, `danger`→red. Optional tilted icon tile, title bar, body.
- **`MethodBadge`** (`.mk-method*`) — HTTP method chip: `GET`→green, `POST`→violet, `PUT`→yellow,
  `PATCH`→action, `DELETE`→pink.

Still scoped (follow-up increments, same pattern — token-driven classes in brand primitives + a thin
`ui-react` wrapper + contract types):

- **`DocCodeBlock`** — tabbed, copy-to-clipboard, optional line numbers (supersedes the bespoke
  `apps/docs/components/docs/code-block.tsx`).
- **Prose scale** — `.mk-prose` heading/paragraph/list/inline-code rhythm for long-form docs.
- **Doc chrome** — top bar, side nav, page shell primitives to replace the reused apps/web chrome.

## Adoption (docs app)

- `Callout` adopted in the Entitlement Patterns guide (alongside the existing `VerdictPill` row).
- `MethodBadge` adopted in the OpenAPI **endpoint detail** header (the dense endpoint list keeps its
  compact list style for now — a deliberately scoped, low-risk first adoption).

## Packages / prereleases

- `@monetizekit/design-tokens` — dark class alias + `paletteModeSelector` (minor).
- `@monetizekit/brand` — §13 primitive classes in `primitives.css` (minor).
- `@monetizekit/ui-react` — `Callout` + `MethodBadge` + contract types (minor).

Published under the `next` tag for the monorepo to consume ahead of the real release-on-merge.

## Verification

- `design-tokens`: unit tests for `paletteModeSelector` + built-artifact assertions for the dual
  selector (incl. palette combos).
- `ui-react`: component + axe-core a11y tests covering `Callout` / `MethodBadge`; `tsc --noEmit` clean.
- docs app: deterministic headless check confirms content repaints light↔dark from the package `.dark`
  (mirror removed); the `Callout` renders styled in both themes with consistent full-page repaint.
